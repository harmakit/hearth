# Hearth Studio

Локальное приложение для нескольких независимых студий. Директор предлагает план, создаёт команду после согласования, назначает задачи, передаёт результаты на ревью и выбирает следующий шаг. Работу видно на канбане, в итогах спринта и в мастерской.

## Запуск

Локальная сборка для macOS на Apple Silicon находится в `dist/0.3.1/`. Данные хранятся отдельно от исходников и проекта. Если открыт предыдущий экземпляр Hearth Studio, закрой его перед запуском новой сборки.

Для разработки нужен Node.js 24 или новее.

```sh
npm ci
npm test
npm start
```

`npm run package:mac` собирает локально подписанное приложение в `dist/<версия>/`. Для тестирования в отдельном профиле подходит переменная `HEARTH_DATA_DIR`.

## Первый спринт

1. Главная «Все студии» показывает активные задачи и открытые входящие. Hearth автоматически проверяет Codex и Claude Code. В **Настройки приложения → Модели приложения** можно ограничить каталог, который по умолчанию открыт целиком. У каждой студии может быть собственный список.
2. Создай студию. Опиши цель, аудиторию и первый результат, выбери язык, подключение и рабочую папку. Папку можно создать в системном диалоге.
3. Нажми «Инициализировать студию». Проверь команду, задачи и критерии. В плане можно изменить названия ролей, имена и модели. «Подтвердить и запустить» создаёт роли и запускает спринт.
4. В «Работе» видны канбан, эпики, истории, спринты и встречи. Из карточки задачи открываются отчёт, ревью и файл результата.
5. Следующий план по умолчанию ждёт решения во «Входящих». Режим меняется в «Настройки → Автономность».

В «Настройки → Автономность» можно задать рабочие дни и часы. Время берётся с Mac. Новые задачи за пределами окна ждут, текущие завершаются. Приложение должно оставаться запущенным. Файлы и отчёты доступны в «Работа → Артефакты». «Удалить студию» находится в её настройках и удаляет записи из Hearth. Папка проекта сохраняется.

## Подключения и перенос

Codex использует временные сессии. Hearth продолжает работу из сохранённых задач, ответов, черновиков и результатов. Для Claude Code нужен авторизованный CLI. Адаптер Claude проверяется на подставном CLI.

В настройках доступны экспорт шаблона, снимок с выбранными артефактами и доказательствами, чтение прежней Hearth и перенос в отдельную папку. Снимок сохраняет связи задач, спринтов, встреч и истории знаний. Для работы с импортированной Git-задачей привяжи репозиторий и проверь указанную версию.

## Работа над проектом

- Число одновременных запусков, рабочее окно и режим питания задаются в настройках студии. В новой студии предусмотрено пять запусков и автоматическая подготовка очереди. Задача, ожидающая ответа, освобождает место для независимой работы.
- В разделе «Работа» есть фазы, бэклог, спринты с переносом карточек и ретроспектива. Разбор очереди можно запросить вручную. В расширенных настройках доступны спринты улучшений. После принятия основной работы Hearth записывает предложенные агентом улучшения отдельными задачами со ссылкой на источник.
- Для правок Git подключи целевую ветку и профиль проверок в настройках проекта. Hearth использует отдельное рабочее дерево, проверяет рабочий результат и кандидата слияния, сохраняет доказательства и привязывает ревью к версии. После слияния чистые управляемые деревья убираются.
- Во «Встречах» можно собрать позиции профильных агентов и сохранить решение. В чате доступны записки директору, вложения и предложения по приоритету. Расход, уведомления и диагностика находятся в настройках студии.

## Подготовка команды

В каждой студии есть директор и коуч агентов. Новая роль получает задачу подготовки. Связанные рабочие задачи ждут её проверки. Директор может поставить повторную подготовку существующему агенту или предложить новую роль, когда меняется работа.

Коуч ищет публичные навыки на GitHub по темам роли. Начальный порог составляет 10 000 звёзд. Он также подбирает открытые материалы и готовит собственные навыки. Утверждённые версии и история обновлений видны в библиотеке. При дообучении директор указывает конкретную работу, которой нужен навык.
