# Порог недельного остатка

- Источник Codex: App Server account/rateLimits/read; берём окно длительностью 10080 минут из общего bucket codex, независимо от primary/secondary. Остаток = 100 минус usedPercent, с ограничением снизу нулём. Время сброса — Unix seconds. Схема подтверждена установленным Codex app-server generate-json-schema, данные проверены в нативной сборке. Разреженные уведомления могут уменьшить известный остаток; для возобновления требуется свежий полный замер.
- Порог приложения (0–100%, пусто — выключен) блокирует новые автоматические попытки во всех студиях, если любой включённый поддерживаемый провайдер достиг порога. Порог студии действует для её директора, фиксированных ролей и разрешённого списка моделей. Глобальная и локальная политики независимы.
- Активные попытки не отменяются. Ручная пауза студии не снимается квотой. Явно отправленные владельцем решения во входящих можно обработать; автоматическая очередь ждёт. При отсутствии первого замера остаток неизвестен, не ноль. Последний низкий замер сохраняет уже действующую паузу после сбоя/перезапуска, в том числе после расчётного времени сброса, до полного свежего измерения.
- При активном пороге приложение обновляет данные не реже минуты по доступности подключения; живые уведомления позволяют поставить новые попытки на паузу раньше. Claude Code: недельные данные не подтверждены штатным интерфейсом, поэтому показано отсутствие поддержки, а не вымышленный остаток.

## Проверка

- [x] Первичное или вторичное недельное окно, независимость от 5-часового окна, несколько bucket.
- [x] Граница порога, две одновременно работающие студии, обе политики независимо.
- [x] Перезапуск и потеря данных после известного низкого остатка; неизвестность до первого замера.
- [x] Нативное приложение: Codex действительно вернул остаток и сброс, Claude Code показал отсутствие данных. В двух новых QA-студиях создано по одному заданию под общим порогом 100%. Обе очереди остались без попыток. После выключения общего порога вторая студия запустилась и завершилась, первая продолжала ждать своего порога 100%. После выключения отдельного порога её задание также завершилось. Оба запуска использовали GPT-6 Luna XHigh как директора.
