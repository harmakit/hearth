> Выполнить план в основной сессии через `superpowers:executing-plans` после согласования владельцем. Отмечать выполненные шаги и проверки.

| | |
| --- | --- |
| Цель | Показать, какие реплики попадают в контекст ответа. Сделать остальную переписку доступной в сворачиваемой истории с пагинацией. |
| Архитектура | Сервис переиспользует один отбор реплик для предпросмотра и запуска. Окно запрашивает ограниченный контекст и страницы истории через существующий мост Electron. |
| Среда | Node.js 24, SQLite, Electron, существующий интерфейс беседы. |
| Спецификация | [Контекст и история беседы](../specs/2026-11-23-conversation-context-design.md). |

## Общие ограничения

- Беседа остаётся привязанной к студии, адресату и задаче, если она выбрана. Потоки входящих директора, комментарии к задаче и их экраны продолжают использовать свои существующие команды.
- Контекст ограничен 24 сообщениями и 24 000 символов текста. Учитывать текст черновика через ту же нормализацию, что при отправке. Текущие вложения передавать по существующим правилам.
- Ранние записи открываются через «Историю». Открытие истории не меняет запрос к модели. Даты, авторы, вложения и действия остаются доступны.
- QA проводить с отдельным профилем и временной студией. Сборку делать в отдельной папке, чтобы сохранить текущий пакет пользователя.

## Сценарии для проверки

| Условие | Ожидаемый результат |
| --- | --- |
| Длинные реплики исчерпали лимит символов раньше лимита сообщений | Граница совпадает с фактическим запросом. Добавление и удаление черновика обновляет её. |
| В беседу отправлено несколько сообщений во время работы агента | Контекст запущенного ответа фиксирован. Остальные отправленные сообщения видны как ожидающие. |
| Новая реплика приходит во время подгрузки истории | На границе страниц нет пропусков и дублей. Прокрутка, раскрытая история и фокус сохраняются. |
| Отправлен черновик с файлом или открыта сохранённая переписка без новых метаданных | Контекст рассчитывается по существующим сообщениям. Вложения и прежние действия работают. |
| Страница запрошена с курсором другой беседы или студии | Сервис отклоняет запрос, интерфейс остаётся в текущей беседе. |

## 2. Просмотр контекста и страницы истории

**Файлы** `core/service.mjs`, `app/bridge.mjs`, `test/service.test.mjs`, `test/app-bridge.test.mjs` и `test/studio-storage.test.mjs`.

**Интерфейсы** Команда `conversationView({ studioId, conversationId, draftText, hasDraftAttachments })` возвращает `{ mode, context, queued, historyCount, historyBefore }`. Режимы `next`, `queued` и `running` различают расчёт для черновика, ожидающий уже отправленный запрос и набор активной попытки. Команда `conversationPage({ studioId, conversationId, beforeMessageId, limit = 20 })` отдаёт `{ rows, nextBefore }` в хронологическом порядке. `nextBefore` содержит ID самой ранней записи страницы при наличии ещё одной страницы.

Проверить, что запрос к другой студии отклоняется, а после открытия старой базы доступны те же сообщения. Для предпросмотра проверить, что посланный ранее запрос в очереди получает собственный расчёт независимо от нового черновика.
