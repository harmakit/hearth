# Hearth Studio · план переноса всего интерфейса

> Исполнение после согласования · применять Superpowers `executing-plans` в основной сессии. Все шаги ниже относятся к будущей реализации.

**Цель.** Перенести утверждённое сочетание компактных экранов и «Сегодня» на реальные данные Hearth и пройти весь путь владельца в собранном приложении.

**Архитектура.** Electron и сервис SQLite остаются источником данных, проверок и команд. Renderer применяет общую визуальную систему, разрешает маршруты на свежем снимке и использует штатные команды для изменения состояния. Строим очередь «Сегодня» поверх существующих данных и сохраняем контекст пользователя отдельно от данных студии.

**Стек.** Electron, JavaScript ESM, CSS, SQLite, встроенный Node test runner, текущий стенд Electron.

**Спецификация.** [Редизайн интерфейса Hearth Studio](../specs/2026-11-22-studio-interface-redesign.md). Локальный референс — `hearth-studio-iterations.html`, режим «Экраны» и очередь из «Маршрутов».

## Общие условия

- Работа только в новом `~/projects/hearth-studio`. Инвентаризация имеющихся незакоммиченных правок предшествует изоляции рабочего дерева. Использовать временные тестовые профили и проекты в `.tmp`.
- Этап интерфейса опирается на штатные команды IPC. Если доступность действия нельзя установить по снимку, расширяем его минимальным подтверждённым полем. Проверки версии, разрешения на запись, ветки, приёмка и доступ к файлам остаются у текущих владельцев этих гарантий.
- Шкала макета 14 px основной текст, 13 px реестр, 12 px пояснения и ID, 23 px заголовок экрана, 18 px заголовок инспектора. Строка от 35 px в компактном режиме и от 42 px в свободном. Контраст текста от 4,5:1, значимых границ и иконок от 3:1.
- Локали `en`, `ru`, `zh-Hans`, `es`, `fr`. Оба цветовых режима, клавиатура, мышь, системное уменьшение движения, ширина окна 590 px и масштаб 200%. Использовать существующий Electron и системную типографику.
- Codex остаётся без resume. Claude проходит контрактные сценарии на текущей фикстуре; реальный провайдер отмечается отдельно при доступном аккаунте. Выполненные нативные проверки Windows и Linux сохраняются как предыдущий отчёт.

## Основные риски при проверке

| Случай | Проверка |
|---|---|
| Смена студии или фоновые обновления сбрасывают форму, прокрутку, фокус или фильтр | T2 фиксирует область по паре «студия + запись» и проверяет возврат. |
| Приёмка показывает устаревший результат или повторно применяет действие | T3 использует исходную версию и идентификатор операции; два решения для одной ревизии дают один итог. |
| Прерванный шаг ещё пишет либо очередь приостановлена | T3 показывает допустимое действие после освобождения процесса; T4 различает запуск, постановку в очередь и ожидание. |
| После сбоя создания уже есть студия или новая папка | T4 проверяет неопределённый ответ, восстановление черновика и запрет повторной записи без сверки. |
| Предыдущий профиль содержит неполные данные или файлы исчезли после импорта и уборки | T5 и T6 показывают недоступность и сохраняют версию, историю и возможность вернуться. |

## T3. «Сегодня», входящие и последствия действий

**Файлы.** Новый `renderer/today-view.mjs`, `test/today-view.test.mjs`; `renderer/workspace-view.mjs`, `renderer/app.mjs`, `renderer/legacy-view.mjs`, `scripts/qa-owner-workspace.mjs`. `core/service.mjs` при необходимости отдаёт минимальную подтверждённую доступность действий.

**Контракт.** `todayItems(snapshot, projectAvailability)` возвращает элементы `{studioId, kind, id, inboxId?, label, createdAt?, affectedTaskIds, target, action}` из S3. Только подтверждённая зависимость влияет на число затронутых задач. Решения вызывают существующие команды, среди них `answerInbox`, `decidePlan`, `resolveReconciliation`, `startTask`, а их результаты берутся из снимка.

Для приёмки передаём `{studioId, inboxId, expectedResult, operationId, decision, answer, reworkTaskId}` по существующему контракту. Вопрос использует версию обращения, варианты и ID вложений. План закрепляет ожидаемую редакцию через `expectedEditVersion`. Для сверки сохраняем `attemptId`, решение и причину. Карточка со ссылкой на скрытое, архивированное или удалённое действие открывает сведения, доступные для просмотра, если они ещё существуют.

## Сверка со спецификацией

| Требование | Задачи |
