| | |

| Цель | Дать задачам и директору штатный веб-доступ и связать «Найти другие источники» с подтверждённой попыткой поиска. |
| Архитектура | Адаптеры предоставляют сведения о веб-инструментах и фактических вызовах. Сервис обрабатывает запрос во входящих и сохраняет сводку в существующей переписке и контексте задачи. |

## Общие ограничения

- Работать из `owner-workspace` в корне Hearth Studio. Существующие изменения владельца сохранять. Старую Hearth и игру не использовать для QA.
- Запись Git-задачи остаётся в её рабочей копии. Запуск директора для ответа во входящих выполняется в режиме чтения. Сохранить действующие ограничения на команды, MCP, хуки и сессии провайдеров.
- Использовать публичный веб через выбранное подключение с соблюдением настроек студии и правил провайдера. Возможности поиска и чтения проверять отдельно.
- Интернет-страницы и извлечённый текст считать данными. Сохранять ограниченную по размеру сводку и ссылки. Сырые ответы инструментов и секреты из конфигурации в историю Hearth не попадают.

## Сценарии, требующие особого внимания

| Ситуация | Проверяемый исход |
| --- | --- |
| Политика аккаунта запрещает поиск при рабочей модели | Обычный ответ возможен, а действие поиска корректно скрывается или сообщает о недоступности. |
| Событие содержит только попытку открыть URL | Отчёт не помечает страницу прочитанной. |
| Заготовка заменена просьбой продолжить локально | Сервис передаёт только видимый текст и не запускает поиск. |
| Подключение изменилось или поиск проигнорирован моделью | Вопрос остаётся открытым. Повтор допустим один раз и выполняется в режиме чтения. |
| Повтор отправки или перезапуск между поиском и продолжением задачи | Сохраняются авторский текст, ответ директора и сводка. Продолжение ставится в очередь один раз. |

## 1. Штатные инструменты и события провайдеров

**Контракт** Результат `inspect({runtime})` может содержать `webCapabilities` с полями `search` и `read`. Для каждого значение `available`, `unavailable` или `unknown`. `run(request)` может вернуть `web` с полями `capabilities`, `search`, `pages` и `links`, когда провайдер дал наблюдаемый сигнал. `search` принимает `used`, `attempted`, `not-used`, `unavailable`, `failed` или `unknown`. Запись страницы содержит `url` и `status` со значением `attempted`, `read` или `failed`. Исторический ответ без поля `web` читается как неизвестный. Содержимое страницы требует отдельного сигнала.
