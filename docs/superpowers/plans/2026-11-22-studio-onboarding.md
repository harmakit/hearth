# Подсказки в Hearth Studio · план реализации

> Черновик для согласования. После утверждения дизайна исполнить в основной сессии через `superpowers:executing-plans`.

**Цель.** Объяснить существующие действия Hearth на рабочем экране от создания студии до первого результата и при ошибках.

**Архитектура.** Рабочие компоненты объявляют место у существующей кнопки и собирают минимальный контекст видимой записи. Общее отображение выбирает одну подсказку для активной поверхности, связывает её с целью и использует единое предпочтение профиля. Выбор подсказки не вызывает рабочих команд.

**Стек.** Electron, HTML, CSS, ESM, Node.js, `node:test`, существующий нативный QA.

**Спецификация.** [Подсказки в Hearth Studio](../specs/2026-11-22-studio-onboarding.md) · [Макет](../../reviews/studio-onboarding.html).

## Общие ограничения

- Использовать штатные маршруты, существующее окно создания, черновик, проверки, согласование, запуск, восстановление и правила публикации.
- Хранить одно предпочтение на профиль. По умолчанию включено, изменение действует на все студии. Макет использует хранилище браузера только для демонстрации.
- Тексты, названия элементов и ошибок проходят текущий каталог `en`, `zh-Hans`, `es`, `fr`, `ru`. Рабочие ID, пути и значения владельца сохраняются.
- Проверить 590 × 470, увеличение до 200%, навигацию клавиатурой, экранное чтение, светлую и тёмную темы и статичную стрелку при `prefers-reduced-motion`.
- Использовать отдельный профиль `HEARTH_DATA_DIR`, временные проекты в `.tmp` и подставной провайдер.

## 1. Настройка профиля и переводы

- [ ] Добавить сценарии к `test/app-bridge.test.mjs`: отсутствие настройки означает `true`, через команду принимается только boolean, новое значение хранится после закрытия и повторного открытия хранилища, привязка к студии отсутствует. Переиспользовать проверки запроса и схему `app_settings`. Запустить `node --test test/app-bridge.test.mjs`, подтвердить провал новых проверок до реализации.
- [ ] Сохранять `onboardingHintsEnabled` по образцу существующих настроек приложения. Добавить boolean в снимок и команду записи в разрешённый список. Публиковать изменившийся снимок тем же способом. Проверить старое хранилище без поля.
- [ ] Добавить флажок «Показывать подсказки» в «Настройки приложения → Интерфейс и уведомления». При ошибке сохранить прежнее значение флажка, вернуть доступность действия и показать причину штатным механизмом. Локализовать тексты из спецификации, подписи подтверждения и сообщения. Повторить целевые тесты и `node --test test/owner-locales.test.mjs`.

## 2. Подсказка у настоящего действия

- [ ] Заполнить `test/renderer-onboarding-hints.test.mjs` наборами состояний из спецификации. Покрыть пустой профиль и черновик, архивную студию, позднее открытие импортированной студии, устаревшую версию первого плана, отсутствие цели или заблокированную цель, ожидание и подготовку без доступного перехода, учебный результат, отчёт без файла и Git-кандидат. Проверить приоритет восстановления и разные типы причин `taskRecovery()`. Запустить новый тест до и после изменений.
- [ ] Ввести чистый выбор `selectOnboardingHint({ enabled, surface, targets })`, который возвращает `null` или `{ key, target, description }`. `targets` объявляет видимые доступные якоря в рендерере активного экрана, включая минимальный контекст: ID записи, вид плана или задачи, вид ошибки либо наличие настоящего файла. Использовать устойчивый `key` из поверхности, объекта и варианта, без новой записи о прохождении. Собирать из одного снимка студии и проверять связь задачи с первым подтверждённым спринтом.
- [ ] Разместить якоря у существующих кнопок создания, плана, подготовки, открытия результата и восстановления. Присоединить `aria-describedby` к цели, добавить ×. Использовать существующий контейнер действий и стили фокуса. Для длинных рядов, узкого окна и увеличения разместить подсказку ниже. У нового якоря три плавных колебания по 850 мс с амплитудой 4 px, при сокращённом движении сразу статичная стрелка. После перерисовки при том же ключе сохранять состояние акцента и прежний фокус.
- [ ] Добавить независимый нативный диалог подтверждения, пригодный для открытия поверх штатного плана. Начальный фокус на «Отмена». Отмена и Escape возвращают его к ×. Подтверждение сохраняет предпочтение и возвращает фокус к прежней цели или заголовку, а при сбое записи диалог остаётся доступным. Сохранить открытый план и изменения формы.
- [ ] Запустить `node --test test/renderer-onboarding-hints.test.mjs test/today-view.test.mjs test/owner-navigation.test.mjs test/workflow.test.mjs test/coach-workflow.test.mjs`. Повторить с выключенной настройкой и подтвердить, что вход в студию, план, запуск, ревью и публикация используют те же обработчики.

## 3. Нативная проверка

- [ ] Дополнить `scripts/qa-owner-workspace.mjs` сценарием пустых экранов, сохранённого черновика, создания и штатного старта. Пройти план, доработку и одобрение, затем упражнение коуча, рабочий файл и восстановление после сбоя. Сверить текущий ID и версию в диалоге, доступный способ открытия файла и отсутствие указателя для неподходящей записи.
- [ ] Проверить ×, повторный снимок, отмену по Escape, сохранение в профиле после перезапуска, глобальное состояние для двух студий, включение через настройки и восстановление фокуса поверх штатного диалога. Смоделировать отказ сохранения и повтор. Проверить узкое окно, 200%, увеличенные тексты, разные темы, клавиатуру и `prefers-reduced-motion`.
- [ ] Запустить `npm test` и `node scripts/qa-owner-workspace.mjs` из корня рабочей копии. Для ручной проверки использовать `HEARTH_DATA_DIR="$PWD/.tmp/onboarding-hints-qa" npm start`. Зафиксировать проверенные платформы и результаты по списку приёмки спецификации.
