# Hearth Studio first desktop slice Implementation Plan

> Use subagent-driven-development for the independent work packages and verification-before-completion for the integrated build.

**Goal.** Ship a local macOS development build that runs the approved studio/task/inbox/report path.

**Architecture.** An isolated renderer calls Electron main through a named IPC command bridge. The service owns SQLite and calls separately tested runtime adapters.

**Tech stack.** Electron, Node ESM, Node SQLite, native HTML/CSS/JS and node:test.

**Spec.** [Hearth Studio](../../design.md)

## Contracts

- `core/service.mjs` exports `createStudioService({ dbPath, run, onChange, notify })`.
  - `service.snapshot()` returns `{studios, tasks, inbox}`. Study data records belong to exactly one studio and expose their stable IDs.
  - Synchronous studio commands are named `createStudio(input)`, `updateStudio({studioId, ...patch})`, `addAgent({studioId, ...input})`, `updateAgent({studioId, agentId, ...patch})`, `createTask({studioId, title, prompt, agentId?})`.
  - Task commands are `startTask({taskId})`, `cancelTask({taskId})`, `answerInbox({inboxId, answer})` and `close()`. `startTask` enqueues locally and returns promptly. `answerInbox` records the response and returns the task to the queue.
  - Studio shape `{id,name,brief,root,language,director:{runtime,model,effort},allowed:[{runtime,model,efforts}],agents:[{id,name,role,mode,runtime,model,effort}]}`. Runtime IDs `codex`, `claude`. Role modes `inherit`, `fixed`, `dynamic`. Roles include `director`, `library`, `engineer`, `editor`, `artist`, `other`.
  - Task shape `{id,studioId,agentId,title,prompt,status,summary,artifact,error,createdAt,updatedAt}`. Status `queued`, `running`, `waiting`, `completed`, `failed`, `interrupted`. The engine may additionally retain account-scoped native session IDs and normalized progress events.
  - Inbox shape `{id,studioId,taskId,kind,title,body,status,answer,createdAt}`. Open/resolved. At minimum typed `question` and `error`.
- `runtimes/index.mjs` exports `run(request)` and `inspect({runtime})`.
  - Run input `{runtime,projectRoot,prompt,model,effort,signal,onEvent,sessionId?}`. `prompt` is generated by the engine. Runtime resolves `{text,sessionId?}` or rejects with a useful error. `onEvent` is optional. Native sessions stay with the original adapter.
  - Inspect resolves `{runtime,available,authenticated?,version?,models?:[{id,name,efforts}],detail?}`. `available` means a suitable executable. Catalog/identity can be incomplete.
- `preload.cjs` exposes `window.hearth.request(command, payload?)` and `window.hearth.subscribe(listener)`. Subscribe returns an unsubscribe function. Success yields the raw result and errors reject with a user-displayable message.
  - Service commands above plus `snapshot`, `pickFolder` (returns path string or null), `inspect` (runtime shape above), `previewImport` (input `{root}`).

## Independent packages

1. **Engine.** Write service tests, implement SQLite and lifecycle, run tests. Cover existing persisted data, crash recovery, blocking question, answer and isolated studios.
2. **Providers.** Write fixture tests, implement both adapters through structured protocols, run tests. Cover error, timeout/abort, blank results, native session scope and unsupported controls.
3. **Renderer.** Build the four screens around a fixture of the bridge. Cover studio creation, launch and response, runtime/role settings and rooms derived from the roster. Use the visual prototype for style.
4. **Migration preview.** Implement and test a read-only inspector for the old folders. Cover a minimal valid source, partial schemas, malformed files and untrusted/symlinked paths.
5. **Desktop and integration.** Create the IPC bridge, Electron shell, development launcher and a smoke fixture. Verify the four screens with the real bridge. Test Codex in a disposable workspace, retain honest Claude test status, and record reproducible launch commands.
