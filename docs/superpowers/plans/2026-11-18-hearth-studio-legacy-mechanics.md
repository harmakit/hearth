# План переноса механик прежней Hearth

> Для исполнителей. После согласования использовать superpowers:subagent-driven-development или superpowers:executing-plans. Отмечать принятые шаги в чекбоксах. На момент подготовки плана реализация этим документом ещё не разрешена.

**Цель** — реализовать полный объём переноса из 39 пунктов с проверяемой доставкой результата, автономной командой и управлением владельца.

**Архитектура** — SQLite хранит фиксируемые переходы, версии и историю. Core планирует и проверяет действия. Electron main выполняет операции Git, файлов, проверок и рантаймов через ограниченные адаптеры. Renderer показывает снимок состояния и отправляет типизированные команды.

**Стек** — существующее Electron-приложение, JavaScript ESM, Node.js 24+, `node:sqlite`, `node:test`, локальный Git, Codex App Server и Claude Code CLI.

**Спецификация** — [перенос механик прежней Hearth](../specs/2026-11-18-hearth-studio-legacy-mechanics-design.md).

## Общие условия

- Исходную Hearth и файлы игры читать только для сверки и пробного импорта. Интеграционные проверки идут в тестовых профилях и временных проектах под `.tmp` Hearth Studio.
- Сохранить Codex и Claude Code, отдельные настройки студий и существующие связи данных. В Codex использовать `thread/start` с обязательным подтверждением `ephemeral: true`. Выполнение восстановления, чата и ревью проектировать без `thread/resume` и привязки к истории провайдера.
- Чекбокс согласования будущих спринтов по умолчанию включён. Онбординг требует отдельного первого подтверждения. Сохранить редактируемый состав, роли и модели до утверждения.
- Планирование, обсуждение, обучение и ревью работают в режиме чтения. Агенты, команды профиля и их дочерние процессы пишут только в управляемый worktree и временную область попытки. Приложение управляет Git-метаданными. Проверки с командами требуют явно подключённого профиля проекта. Сетевые и внешние действия используют отдельные разрешения владельца.
- Команды записи используют идентификатор операции, проверяют студию, версию и право. Повтор запроса возвращает известный итог. Миграции с сохранением старых записей проверяются на копии базы.
- Пункты 22–24 реализуются через профили студий. Старая игра подключается после приёмки на тестовом проекте и отдельного решения владельца.

## Карта этапов

| Этап | Задачи | Результат для приёмки |
|---|---|---|
| A. Доставка | T0 → T1 → T2 → T3 | Задача правит свою Git-копию, проходит проверку и ревью, доходит до безопасного слияния. Доказательства переживают уборку. Текстовый цикл по-прежнему работает. |
| B. Работа студии | T4 → T5 → T7 | Независимая работа продолжается при блокировках. Директор управляет фазами, спринтами, грумингом, техдолгом и встречами. |
| C. Команда и владелец | T6 → T7, T8, T9 | У роли появляются проверенные знания и история. Владелец общается с командой, видит расход и может перенести студию. |
| Приёмка | T10 после A–C | Сценарии проверены на собранном `.app` и тестовых провайдерах, результаты приёмки сохранены. |

T6 можно вести параллельно с T1–T3, T8 — после T4 параллельно с T5–T7. При независимой реализации общие точки подключения в `core/service.mjs`, `core/workflow.mjs`, `app/main.cjs` и `renderer/app.mjs` вносит один интегратор. T7 ждёт T4–T6, T9 ждёт готовых схем T1–T8. Каждый блок сначала проходит целевые тесты, затем проверку совместимости и ревью перед интеграцией.

## Риски для приёмки

| Случай | Кто проверяет |
|---|---|
| Просроченная попытка ещё жива, а одна из двух задач ждёт владельца | T4 проверяет аренду, изоляцию ожидания и рестарт между записью эффекта и квитанцией. |
| Кто-то изменил ветку после ревью или добавил незарегистрированный файл перед уборкой | T2 сверяет версию перед продвижением, T3 повторно проверяет рабочую копию перед удалением. |
| Повторное обучение не прошло, а участника ждут на другой встрече | T6 проверяет черновик и публикацию, T7 — связь конкретного потребителя и исключение. |
| Директор оценивает техдолг, пока владелец редактирует настройки | T5 проверяет, что ручные правки выигрывают и следующий план использует сохранённые условия. |
| Перенос содержит выбранное видео, ссылку на недоступный файл и старый язык отчёта | T9 сверяет файл и ссылки, показывает отсутствующее, сохраняет язык и проверяет отсутствие лишних данных. |
