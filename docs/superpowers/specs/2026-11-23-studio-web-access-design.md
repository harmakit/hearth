# Веб-доступ для задач и директора

Согласовано 23 ноября 2026 года · пункт 2 бэклога

## Что меняется

Директор и исполнители могут по умолчанию искать и читать публичные источники через инструменты выбранного провайдера. Поиск доступен и в обычной задаче, и при ответе владельцу. При работе с Git запись остаётся в управляемой рабочей копии задачи. Ответ директора во входящих выполняется в режиме чтения.

Сейчас Hearth отключает `web_search` при запуске Codex App Server. В Claude Code списки инструментов содержат файловые операции для изолированного запуска или пустой список для запуска без файлового доступа. Во входящих Hearth предлагает «Найти другие источники» по тексту вопроса, а отправку обрабатывает как обычный ответ владельца. У приложения нет подтверждения, что поиск состоялся.

## Подключения

Предлагаю использовать штатные инструменты обоих провайдеров. Они работают с уже выбранными аккаунтом и моделью и дают события вызова. Простой вариант с одними флагами запуска разрешил бы веб-доступ, но оставил бы кнопку без проверяемого результата. Для явного запроса на поиск добавляем проверку фактического вызова и сохраняем её итог в Hearth.

| Подключение | Как даём веб-доступ | Откуда берём сведения о запуске |
| --- | --- | --- |
| Codex App Server | Запрашиваем `web_search = "live"` в запусках, где это разрешено. Профиль запуска сохраняет `network.enabled = false` для команд. | Учитываем эффективный режим и ограничения провайдера. Событие `webSearch` различает поиск и попытки открыть страницу или найти текст на ней. |
| Claude Code | Добавляем `WebSearch` и `WebFetch` к инструментам соответствующего режима, включая запуск без файловых инструментов. Разрешения задаём для этих инструментов с соблюдением управляемых правил и штатной проверки адресов. | Учитываем доступные инструменты и результаты их вызовов в `stream-json`. Файловые инструменты, ограниченный режим и изоляция сохраняют текущие границы. |

Временные сессии, запрет внешних MCP и хуков при запуске, границы доступа к каталогу и ограничения команд сохраняются. Текст с публичной страницы служит материалом для проверки. Он не даёт агенту разрешения отправлять содержимое проекта, менять файлы или выполнять команды.

## Входящие и продолжение задачи

1. Карточка предлагает «Найти другие источники», когда вопрос связан с источниками и следующий запуск директора может использовать поиск. Возможность определяется по выбранному подключению и известным ограничениям, а на старте перепроверяется. Если поиск заведомо недоступен, карточка предлагает продолжить с материалами студии, уточнить, что требуется, или приложить источник там, где карточка уже поддерживает вложения.
2. Кнопка заполняет редактируемое поле. «Отправить» сохраняет видимый текст, версию входящего и ID операции через существующий маршрут. Отправка формулировки о поиске, в том числе осмысленно изменённой владельцем, запускает поиск в ближайшей обработке этого ответа директором. Отредактированная просьба продолжить локально проходит обычный путь ответа.
3. Если поиск доступен, для такого запроса ожидаем событие реального поиска в той же попытке. При пропущенном вызове допустима одна повторная попытка в режиме чтения. При недоступности после отправки или отсутствии вызова после повтора директор сохраняет ответ с точным статусом и оставляет вопрос открытым для следующего решения.
4. Директор сохраняет ссылки и краткий итог в переписке. Когда результат позволяет продолжить задачу, передаёт эту сводку вместе с текстом владельца в существующую очередь. При повторной отправке операции или перезапуске приложения использует существующие проверки версии и дедупликацию.

| Что произошло | Что увидит владелец |
| --- | --- |
| Поиск недоступен в текущем запуске | Причину, если провайдер её сообщил, и доступные действия с материалами студии. |
| Поиск можно было вызвать, но вызова не было | Сообщение о том, что поиск не выполнился, и доступный следующий шаг. |
| Поиск состоялся, отдельная страница не открылась | Ссылку, известную причину сбоя и другие источники, если их удалось найти. |
| Найдена или прочитана часть источников | Ссылки, отмеченные как найденные или прочитанные, сведения из прочитанных страниц и факты, которые ещё предстоит сверить. |

Событие попытки открыть URL подтверждает попытку. Статус «прочитано» требует полученного содержания, а отчёт связывает подтверждённый факт с конкретной страницей. При неполном ответе провайдера Hearth оставляет факт непроверенным. Смена модели и провайдера подчиняется существующим настройкам студии.

В отчёте отдельно видны попытка открыть страницу и ссылка, которую предложила модель без подтверждения инструмента. Если владелец просит оставить вопрос открытым, сводка сохраняется в переписке без продолжения задачи.

## Порядок реализации и проверки

1. В `runtimes/` включить штатные инструменты независимо от доступа к проекту. Расширить тесты адаптеров, чтобы они различали доступность инструмента, вызов поиска, чтение и сбой страницы. Проверить прежние границы записи для Codex и Claude Code.
2. В `core/` связать результат веб-вызовов с текущей попыткой, продолжением задачи и историей ответа. Использовать одни правила для ручных и спринтовых задач. Добавить проверки отправки и редактирования заготовки, изменения возможностей после открытия карточки, повторной отправки и повторного открытия истории.
3. В существующем интерфейсе входящих показывать доступные варианты и исход поиска. Проверить русский интерфейс и остальные поддерживаемые локали. Проверить, что до отправки поиск не начинается, а после отправки в результате видны ссылки и статус проверки.
4. Пройти `npm test`, `npm run package:mac` и проверку собранного приложения на отдельном профиле. На временной копии `guys inc` отработать исторический запрос с рабочим и недоступным источниками, затем проверить переписку после перезапуска. Для живых проверок использовать отдельные профили провайдеров. Если на стенде нет авторизованного подключения или сети, отдельно зафиксировать результат тестов с подставным CLI и блокер живой проверки.

Исходная проверка на `a12f446` прошла 325 тестов. Установленные CLI сообщили версии Codex `0.171.0` и Claude Code `2.1.330`. Живой поиск из Hearth на этом этапе ещё не проверялся.
