# Hearth Studio · доработки после проверки текущей сборки

Обновлено 23 ноября 2026 года. Текущая сборка — 0.4.0, коммит `92cf717` с ручным созданием локального репозитория. Начать работу по этому списку после проверки текущей сборки. Файл хранит решения и открытые вопросы для будущих спецификаций.

## 1. Git в каждой студии

- [ ] При создании или подключении студии проверять корень проекта. Если там ещё нет репозитория, Hearth создаёт локальный Git и управляемую ветку без дополнительного вопроса. Настройку выбора ветки показывать для существующего репозитория. Его история, рабочие изменения и текущий индекс сохраняются.
- [ ] В настройках студии показывать понятное состояние «Локальный репозиторий подключён» и, когда это уместно, короткое имя ветки. Полный `refs/heads/…` доступен в расширенных настройках или по действию копирования. На экране подтверждения слияния показывать конкретную ветку назначения.
- [ ] Для ранее созданных студий без Git использовать тот же порядок при первом подключении к новому формату. Проверить новую папку, существующую папку с файлами, существующий репозиторий и папку внутри чужого репозитория. Для существующей папки принять текущее безопасное поведение за основу: пустой первый коммит без автоматического добавления файлов. Правила переносимой папки и исключения приватных данных из Git сохраняются.

## 2. Веб-доступ для задач и директора

- [ ] Дать директору и исполнителям штатный поиск и чтение публичных страниц по умолчанию там, где провайдер поддерживает эти инструменты. Доступ к инструментам и проектным файлам задаётся отдельно. Запись в Git-задаче остаётся в её рабочей копии.
- [ ] Подключить «Найти другие источники» к реальному поиску. После «Отправить» следующий запуск должен использовать доступный веб-инструмент и вернуть ссылки, что удалось прочитать и что осталось непроверенным.
- [ ] Показывать отдельно, когда веб-инструмент недоступен и когда не открылась конкретная страница. Варианты во входящем должны соответствовать возможностям текущего запуска. Проверить сценарий `guys inc` на временной копии: задача проверяет исторические источники, а при сбое предлагает выполнимый следующий шаг и сохраняет переписку.

## 3. Скачивание навыков и проверка обновлений

- [ ] Когда веб-доступ готов, коуч сам ищет и оценивает кандидатов. Hearth скачивает выбранный публичный навык, хранит репозиторий, путь, точный коммит и сведения о лицензии. Использовать существующую библиотеку и штатные `SKILL.md` как основу.
- [ ] При запуске студии проверять, есть ли более новые версии зарегистрированных навыков. Показывать текущую и доступную версии. Применение обновления — отдельное решение, а действующие запуски продолжают работать с закреплённой версией. При недоступности GitHub студия может работать с уже скачанным навыком.
- [ ] Проверить обнаружение новой версии, сохранение старой после отказа от обновления, работу без сети и соблюдение пауз при ограничении запросов GitHub.

## 4. Порог остатка недельного лимита

- [ ] В настройках приложения добавить порог `N%` недельного остатка для поддерживаемых подключений. При достижении порога останавливать новые автоматические запуски во всех студиях. В каждой студии дать отдельный порог для остановки её запусков. Оба уровня действуют независимо, глобальная пауза распространяется и на студии с собственным порогом.
- [ ] Брать остаток и время сброса из поддерживаемого интерфейса провайдера. Показывать провайдера, остаток, причину паузы и время следующего сброса, когда оно известно. Значение «неизвестно» отображать отдельно от исчерпанной квоты.
- [ ] На этапе дизайна решить, как поступать с выполняющимися задачами, когда возобновлять работу, как обрабатывать устаревшие данные и как применять общий порог при нескольких подключениях. Отдельно проверить, какие провайдеры и типы аккаунтов действительно отдают недельное окно.
- [ ] Проверить достижение и пересечение порога, одновременную работу двух студий, отдельно глобальную и студийную паузу, перезапуск приложения и недоступные данные квоты.
