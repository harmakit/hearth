# Hearth Studio · доработки после проверки текущей сборки

Обновлено 25 ноября 2026 года по итогам сверки диалога, спецификаций и отчётов о проверках. Текущая сборка — 0.4.0. Файл хранит решения и открытые вопросы для будущих спецификаций.

## 1. Git в каждой студии

- [x] При создании или подключении студии проверять корень проекта. В новой истории целевая ветка — `main`. В существующем Git выбирается `main` или `master` с учётом основной ветки репозитория. Явный выбор через мастер сохраняется.
- [x] Сливать проверенную ревизию в чистую открытую ветку и обновлять файлы проекта. Проверять индекс, рабочие файлы и актуальность Git-ревизии. Существующие назначения веток сохраняются.
- [x] В настройках студии показывать понятное состояние «Локальный репозиторий подключён» и, когда это уместно, короткое имя ветки. Полный `refs/heads/…` доступен в расширенных настройках или по действию копирования. На экране подтверждения слияния показывать конкретную ветку назначения.
- [x] Для ранее созданных студий без Git использовать тот же порядок при первом подключении к новому формату. Проверить новую папку, существующую папку с файлами, существующий репозиторий и папку внутри чужого репозитория. Для существующей папки принять текущее безопасное поведение за основу: пустой первый коммит без автоматического добавления файлов. Правила переносимой папки и исключения приватных данных из Git сохраняются.

Проверены реальные Git-репозитории, перенос старой студии без Git, повторное открытие после явного отключения, чужие вложенные папки, репозиторий без первого коммита. В нативном мастере создана студия с ранее существовавшим черновиком и другая с выбором свободной ветки; HEAD, исходный индекс и рабочие изменения сохранены. [План](superpowers/plans/2026-11-25-default-project-git.md)

## 2. Веб-доступ для задач и директора

- [x] Дать директору и исполнителям штатный поиск и чтение публичных страниц по умолчанию там, где провайдер поддерживает эти инструменты. Доступ к инструментам и проектным файлам задаётся отдельно. Запись в Git-задаче остаётся в её рабочей копии.
- [x] Подключить «Найти другие источники» к реальному поиску. После «Отправить» следующий запуск должен использовать доступный веб-инструмент и вернуть ссылки, что удалось прочитать и что осталось непроверенным.
- [x] Показывать отдельно, когда веб-инструмент недоступен и когда не открылась конкретная страница. Варианты во входящем должны соответствовать возможностям текущего запуска. Проверить сценарий `guys inc` на временной копии: задача проверяет исторические источники, а при сбое предлагает выполнимый следующий шаг и сохраняет переписку.

Раздельные статусы и сохранение переписки проверены с подставным Codex и в двух отдельных студиях на macOS. Живой Codex проверил историческую основу выпуска и вернул источник в беседе. Контрольный запуск с несуществующим адресом Википедии дошёл до вопроса владельцу; после выбора альтернативного поиска директор сохранил найденные ссылки NASA, задача возобновилась и вернула проверенный ответ. Живая проверка Claude остаётся в разделе 6. [План и результаты проверки](superpowers/plans/2026-11-23-studio-web-access.md)

## 3. Скачивание навыков и проверка обновлений

- [x] Когда веб-доступ готов, коуч сам ищет и оценивает кандидатов. Hearth скачивает выбранный публичный навык, хранит репозиторий, путь, точный коммит и сведения о лицензии. Использовать существующую библиотеку и штатные `SKILL.md` как основу.
- [x] При запуске студии проверять, есть ли более новые версии зарегистрированных навыков. Показывать текущую и доступную версии. Применение обновления — отдельное решение, а действующие запуски продолжают работать с закреплённой версией. При недоступности GitHub студия может работать с уже скачанным навыком.
- [x] Проверить обнаружение новой версии, сохранение старой после отказа от обновления, работу без сети и соблюдение пауз при ограничении запросов GitHub.

Проверка точного пути и коммита GitHub, отказа, офлайн-работы, совместного cooldown, откладывания обновления до завершения активных попыток и переноса снимка выполнена с воспроизводимыми подставными ответами GitHub. Нативный интерфейс проверен в отдельной фикстуре: отказ, явное применение, оба файла SKILL.md и смена привязки роли. Живой каталог в ночном прогоне возвращал ограничения запросов; живую смену версии из публичного репозитория не удалось подтвердить. [План](superpowers/plans/2026-11-25-skill-versions.md)

## 4. Порог остатка недельного лимита

- [x] В настройках приложения добавить порог `N%` недельного остатка для поддерживаемых подключений. При достижении порога останавливать новые автоматические запуски во всех студиях. В каждой студии дать отдельный порог для остановки её запусков. Оба уровня действуют независимо, глобальная пауза распространяется и на студии с собственным порогом.
- [x] Брать остаток и время сброса из поддерживаемого интерфейса провайдера. Показывать провайдера, остаток, причину паузы и время следующего сброса, когда оно известно. Значение «неизвестно» отображать отдельно от исчерпанной квоты.
- [x] На этапе дизайна решить, как поступать с выполняющимися задачами, когда возобновлять работу, как обрабатывать устаревшие данные и как применять общий порог при нескольких подключениях. Отдельно проверить, какие провайдеры и типы аккаунтов действительно отдают недельное окно.
- [x] Проверить достижение и пересечение порога, одновременную работу двух студий, отдельно глобальную и студийную паузу, перезапуск приложения и недоступные данные квоты.

Поддерживается недельное окно Codex App Server (определяется по длительности, а не позиции primary/secondary). Claude Code показан как неподдерживаемый источник недельной квоты. Активные попытки не прерываются; неизвестный остаток не считается нулём; если предыдущий замер уже вызвал паузу, она остаётся до нового достоверного замера. Два живых задания в двух QA-студиях дождались снятия общего и затем отдельного порога. Реальный Codex вернул недельный остаток и дату сброса. [План](superpowers/plans/2026-11-25-weekly-quota.md)

## 5. CodeGraph

- [x] Сравнить полные агентские задачи с CodeGraph и без него. Замерить расход токенов, время и точность на одинаковых задачах. Проверить применимость к GDScript и актуальность индекса в отдельных Git worktrees.
- [x] По результатам решить, включать ли его автоматически для подходящих проектов. Предусмотреть общую настройку и переопределение в студии. Три пары живых задач на JavaScript завершились с одинаково корректными результатами, включая две принятые Git-доставки в каждой студии. Установленный отдельно инструмент подключается по PATH; при недоступности работает обычная навигация. [Отчёт эксперимента](reviews/2026-11-19-codegraph-trial.md)

### Доработки, найденные в живом прогоне

- [x] Критерии подготовительной задачи проверяются до запуска зависимых работ. Исполнитель и проверяющий видят, что поручено следующей задаче. Проверяющий видит сохранённое уточнение владельца.
- [x] Ревью Git-задачи проверяет точный кандидат и применимые проектные проверки. Сводная проверка видит актуальные коммиты, результаты ревью и проверок. Ссылки в отчётах ведут к файлам от корня проекта.
- [x] После отклонения сводной приёмки карточка подсказывает, какую работу вернуть на доработку. Повторная приёмка открывается после проверки обновлённого результата.
- [x] Повтор Git-задачи получает сохранённые текстовые черновики из своей рабочей копии. К готовому ответу о продолжении можно дописать указания: Hearth передаст их исполнителю и возобновит задачу.
- [x] Git-сравнение между спринтами проверяет файлы принятой версии. Отдельно сохранённые артефакты остаются доступны в контексте задач.
- [x] Задача и ревью получают список Git-файлов своей версии и материалы двух предыдущих спринтов. В живой проверке пьесы это позволило сверить ссылки и роли по обоим выпускам персонажей.
